## 2. Что прототипировано

* **Словарь.** `hyph-be.tex` (hyph-utf8, Maksim Salau, **MIT**, 3236 паттернов, «Правілы 2008, закон 420-З») — используется, свой движок Liang на Dart (`be_hyphenator.dart`). Hunspell `hyph_be_BY.dic` (CC BY-SA 4.0 / LGPLv3, copyleft) — **не взят**. Правила поверх TeX: min 2 слева / 3 справа, нет одиночных букв, нет разрыва у апострофа и перед `ь`/`ў`, `дз/дж` неделимы, каждый фрагмент с гласной (по одному разрыву между гласными: «ця-рплі-ва-сці», не «ця-р-п-лі»), слова с цифрами/латиницей/ЗАГЛАВНЫЕ/с NBSP не трогаются, у составных — разрыв после дефиса. Строгое толкование апострофа («аб’-ява» допустимо или нет) — **нужна проверка лингвистом**; сейчас консервативно запрещено.
* **A** — `Text.rich` / `flutter_html`, `justify` (контроль). **C** — `left` (контроль).
* **D** — тот же рендерер B2, но `left` (рваный правый край) **с** переносами; добавлен по запросу заказчика («переносы нужны и вне justify»).
* **B1** — те же стандартные виджеты + `U+00AD` из белорусских паттернов.
* **B2** — отдельный рендерер одного абзаца (`justified_hyphen_text.dart`, `RenderBox`): исходная строка не меняется (нет `U+00AD`, нет `-\n`), дефис *рисуется*; оптимальная разбивка (динамическое программирование в стиле Кнута–Пласса: штрафы за растяжение, за дефис, ≤3 переноса подряд, запрет оставлять хвост <3 букв); justify растягивает только пробелы; весь span-tree абзаца (курсив, выделение предложений, рубрика, ссылка, NBSP) — одна единица. Для HTML-сценария `<p>` разбирается в один `TextSpan` на абзац.

### Факт про U+00AD (Flutter 3.38.9, и Chrome CanvasKit)
Движок **рвёт строку** в точке `U+00AD`, но **дефис не рисует** (тест `B1 control` проверяет пиксели; скриншот Chrome `out/web_chrome_B1_softhyphen_no_hyphen.jpg`, B1-колонки на всех листах). Значит одно лишь «вставить мягкие переносы» даёт невидимые переносы «па|шаны» и портит строку невидимым символом. **Flutter 3.41.4 (версия приложения, Dart 3.11.1, engine e4b8dca3): тот же результат** — тест `B1 control` прошёл в изолированной копии (`./compare_sdk.sh 3.41.4`): разрыв в U+00AD есть, дефис не рисуется. master — **не проверен**.

**Копирование/доступность U+00AD** (`selection_test.dart`, 3.38.9): выделить всё + копировать в `SelectableText` даёт строку с невидимыми `U+00AD` внутри слов («Дабраслаў<SHY>лённы») — цитата загрязнена; semantics тоже содержит их. B2 копирование/выделение не реализует (см. §5).

## 3. Результаты на фикстуре (этап 1, пересчитано на этапе 2)
Ширина колонки = ширина экрана − 32 dp. Масштаб 100/150/180 % = 16/24/28,8 dp. **Одна** метрика «плохая строка» на строку (признаки не суммируются, `LabMetrics.isBad`):
* justify: пробел растянут больше чем втрое (растяжение > 2 обычных пробела, ≈ 0,6 em) или строка из одного слова, не заполняющая 80 % ширины; мягкая метка «пробел вдвое» (> 1) в таблице не участвует;
* left: строка короче колонки больше чем на 25 %.

**Проценты justify и left считаются по разным критериям и напрямую не сравниваются**: сравнивать можно A с B1/B2 (justify) и C с D (left).

## 3а. Этап 2: реальные чтения и порог адаптивного выравнивания
**Данные.** Реальные белорусские чтения из локального `assets/content/readings.json.gz` (читаются только на чтение, ничего не копируется и не меняется): 1823 текста (чтение 1, 2, Евангелие), медиана 719 знаков, **9 из 1823 содержат HTML** (почти всё — простой текст со строками через `\n`, абзацы разделены пустой строкой, которую приложение схлопывает). Поэтому основной путь — `Text.rich`, HTML — редкость.
**Исправлено в метриках:** единый признак «плохая строка» (см. §3); в замерах через `TextPainter` исправлен пропуск строк после жёсткого `\n` (до правки счёт терял абзацы после первого перевода строки — затронуло только замер порога, не листы этапа 1).

**Порог.** Измерено на 152 реальных чтениях (выборка), 4 шрифта × 6 масштабов (0,7–1,8) × 6 ширин (288–680 dp), 21 448 замеров; метрика — доля плохих (justify) строк абзаца при стандартном рендерере; «знаков в строке» = ширина / средняя ширина буквы белорусской прозы в данном шрифте и размере (`out/real_threshold_summary.txt`):

| знаков в строке | доля плохих строк (среднее) | абзацев с ≤15 % плохих |
|---|---|---|
| 18–22 | 63 % | 0 % |
| 26–30 | 42 % | 3 % |
| 34–40 | 28 % | 21 % |
| 40–50 | 21 % | 40 % |
| 50–70 | 8 % | 78 % |
| 70+ | 1 % | 97 % |

Начальная гипотеза 25–30 знаков **не подтвердилась**: при 26–34 знаках ~40 % строк всё ещё плохие. Выбран порог **36 знаков** (плато 34–38): оставляет justify у 67 % замеров; из оставленных 17 % абзацев с >25 % плохих строк и 5 % с >40 %; из переведённых в left лишь 4 % выглядели бы хорошо в justify. Для типичного телефона (358 dp) это: 100 % шрифта (≈42 знака) — justify; 150 % (≈28) и 180 % (≈23) — left.
Оговорка: по шрифтам различие заметно (Literata хуже, Old Standard TT / Kurale лучше при тех же 34–40 знаках), единая константа — компромисс.

**Результат на реальных чтениях** (~38 чтений × 4 шрифта × 4 ширины × 3 масштаба, светлая тема; `out/real_modes_summary.txt`). «AD» — адаптивное выравнивание на стандартном рендерере (то, что вошло в приложение); строки оцениваются по реально применённому выравниванию, поэтому AD сопоставим только внутри своих семейств:

| | строк | плохих | с переносом | justify-строк |
|---|---|---|---|---|
| A (сейчас) | 56 344 | 43,3 % | — | 100 % |
| **AD (адаптивное)** | 56 344 | **16,9 %** | — | 16 % |
| B2 (justify + переносы) | 54 924 | 23,6 % | 25,8 % | 100 % |

По масштабам: при 100 % A 23,3 % / AD 16,3 % / B2 6,4 % / D 1,3 %; при 150 % A 43,3 % / AD 12,8 % / B2 23,4 % / D 8,5 %; при 180 % A 53,2 % / AD 20,4 % / B2 32,3 % / D 14,0 %. Вывод: **B2 хорош при 100 % (≥33 знаков)**, при крупном шрифте justify остаётся плохим даже с переносами; D надёжнее всего, но это уже режим left. (Цифры B2/D после добавления типографских правил этапа 3 — они «стоят» 2–5 пунктов: запрет разрыва после предлога/сокращения/перед числом и запрет переносить имена уменьшают свободу разбивки.)

## 3в. Этап 4: итоговый режим (решение принято: B2 + D поверх AD)
Реализован в стенде как `FinalReading` (`lib/final_scene.dart`): «Па шырыні» при ≥36 знаков → B2, иначе D; «Па левым краі» → D; не-проза (стихи, псалмодия, рубрики) → стандартный рендерер. Скриншоты и проверки: [FINAL.md](FINAL.md). Регрессии (`final_test.dart`, 9 тестов): выбор B2/D, тождество с правилом #149, копирование исходного текста, формат, отсутствие переполнений, неизменность псалма.

## 4. Вывод
* **Не использовать B1** (стандартный рендерер + `U+00AD`): дефиса нет, строка «грязная», копирование портит цитату.
* **Безопасное улучшение — AD** (адаптивное выравнивание на стандартном рендерере, порог 36 знаков, реализовано в отдельном PR приложения): на реальных чтениях доля плохих строк 43 % → 17 % при сохранении копирования, выделения, подсветки и HTML.
* **D (left + переносы)** — лучший по качеству (9,3 % плохих строк на реальных чтениях, 2,2 % строк с переносом), но требует собственного рендерера и ещё не закрывает выделение/копирование.
* **B2 (justify + переносы)** хорош при 100 % шрифта (6,4 % плохих), но при 150–180 % всё равно 23–32 % плохих строк и 26–29 % строк с дефисом — для крупного шрифта AD/D лучше.
* **Целевая схема после приёмки** (визуально — `out/real/epistle_Literata_100_360_light.png`: при 100 % на 360 dp B2 заметно лучше A/AD, у которых там одинаковый justify): «Па шырыні» → B2, пока в строке ≥36 знаков, иначе D; «Па левым краі» → D. AD остаётся запасным безопасным вариантом без собственного рендерера.
* Сохраняем оба режима: «Па шырыні» (с автоматическим откатом на left при слишком узкой колонке) и «Па левым краі»; переносы нужны в обоих режимах → следующий кандидат D (left) и B2 (justify, только при достаточной ширине), после закрытия требований этапа 3.

### Остаточные дефекты B2 (видны на скриншотах)
строки с одним растянутым пробелом («вінны      па-»), «5,   3–12» (ссылки в фикстуре без NBSP — в проде нужна склейка), много дефисных строк, нет кернинга на стыках фрагментов, у фрагментов разных кеглей общая верхняя линия.

## 5. Риски интеграции (интеграция не делалась)
* `_ReadingText` (plain): `Text.rich` → заменить на B2-виджет; **выбор/копирование не реализованы** в B2 (нужен `Selectable`/`SelectionRegistrant`; без этого `SelectableText.rich` в `reading_detail_screen.dart:128` и `SelectionArea` в `devotional_office_reader.dart` теряются) — главный блокер. Семантика: label = исходный текст (проверено тестом).
