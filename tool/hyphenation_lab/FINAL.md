# Приёмка: итоговый адаптивный режим с переносами (B2 + D поверх AD из #149)

Решение принято (B2 и D объединяются). Здесь — только итоговый режим, на реальных текстах из `assets/content` и с оформлением приложения (палитра, Literata, межстрочный 1,68, поля 16 dp). В приложение **не интегрировано**.

## Логика
| Сохранено пользователем | Строка | Применяется |
|---|---|---|
| «Па шырыні» | ≥ 36 знаков (порог #149, без изменений) | **B2** — по ширине + переносы |
| «Па шырыні» | < 36 знаков (узкий экран / крупный шрифт) | **D** — по левому краю + переносы |
| «Па левым краі» | любая | **D** |

Код: `lib/final_scene.dart` (`finalChoice`, `FinalReading`). Критерий «≥ 36» — тот же, что в #149 (проверено тестом на всех шрифтах/масштабах/ширинах). Переносы считаются при отрисовке; исходный текст не меняется. Тип блока: **проза** → B2/D; **стихи/псалмодия** (явные переносы строк, `*`, `†`) и **рубрики** → существующий рендерер без изменений.

## Проверки (реально выполнены, Flutter 3.38.9, `flutter test` в `tool/hyphenation_lab`: 230 тестов проходят)
* `final_test.dart` (9): таблица выбора B2/D; **тождество с правилом #149** для 4 шрифтов × 4 масштабов × 5 ширин; рендерер действительно следует выбору, сохранённая настройка не меняется, «Па левым краі» → всегда D; «выделить всё + копировать» = исходный текст (B2 и D, без добавленных переносов/`U+00AD`); **нет переполнения и строки собираются обратно в текст** на реальных чтениях × 4 шрифта × 2 масштаба × 2 ширины × 2 настройки; молитва (markdown): жирный/курсив есть, маркеры не показываются; смешанный HTML: проза → рендерер переносов, рубрики/стихи → стандартный, спецсимволы сохранены; **псалом не меняется** (нет рендерера переносов, пиксели не зависят от настройки); классификация блоков.

## Ограничения и непроверенное
* **Выделение и доступность на реальном устройстве** (сенсорные ручки/тулбар, TalkBack, VoiceOver) — **не проверены**; в тестах только мышь/программное выделение и semantics-узел.
* Определение типа блока — эвристика стенда (`<br>`, `*`, `†` → стихи; только красный текст → рубрика). В приложении гимны, антифоны, библейские песни и респонсории распознаются классами/структурой (`ora-ant`, `ora-psalm`…) — при интеграции нужно использовать их, а не эту эвристику; в стенде они не показаны отдельными примерами.
* Красные рубрики из старого HTML (`color:#ff0000`) в стенде приводятся к цвету рубрики упрощённо; в приложении это делает `formatLiturgicalHtml`.
* Правила переносов (апострофы, составные слова, имена) требуют подтверждения лингвиста; сомнительное оставлено без переноса (имена внутри предложения, слова с цифрами, сокращения).
* Не проверялись: Flutter master, длинные главы Библии на устройстве (производительность измерена только в тестах: самое длинное чтение — 140–280 мс).
* Firebase: 0 обращений с моей стороны (стенд читает только локальный бандл); бандл, тексты и SDK приложения не менялись; APK не собирался.
