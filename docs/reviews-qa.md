# Ацэнка прыкладання: што рэалізавана і як правяраць

PR1 з пакета «flutter_reviews» (2026-11-12): аўтаматычны сістэмны запыт ацэнкі,
ручная спасылка ў краму і выключальнік. Апытанне ўзроўню задаволенасці 1–5
(PR2) наўмысна **не** ўваходзіць: для яго няма ўзгодненага сервернага
кантракту.

## Што робіць код

| Частка | Файл |
|---|---|
| Стан (толькі лакальна, Hive-скрынка `app_review_v1`) | `lib/review/app_review_state.dart`, `app_review_storage.dart` |
| Правілы: ≥7 сутак, ≥5 розных каляндарных дзён, паўза ≥120 сутак, ≤2 спробы за 365 сутак, адна спроба на версію, ход гадзінніка назад блакуе | `lib/review/app_review_policy.dart` |
| Выклік сістэмнага API (`in_app_review`), ручная старонка крамы | `lib/review/native_review_adapter.dart` |
| Кантролер (спроба запісваецца **перад** выклікам, падвойны трыгер немагчымы) | `lib/review/app_review_controller.dart` |
| Спакойны момант: вяртанне з тэксту на корань раздзела (`/hours`, `/readings`, `/prayers`, `/bible`) + 4 с без руху, не пры клавіятуры, дыялогу, туры, не ў фоне | `lib/review/app_review_host.dart` (падключаны ў `AppShell`) |
| Налады: «Ацаніць дадатак» і «Не прапаноўваць ацэнку» пад «Зваротная сувязь» | `lib/review/app_review_settings_section.dart` |

## Што захоўваецца і што адпраўляецца

- Лакальна: час першага запуску, спіс каляндарных дзён выкарыстання (да 30),
  часы і версіі нашых выклікаў API, стан выключальніка. Нічога не адпраўляецца
  ў сетку, аналітыка v2 не чапаецца (яна ў звычайнай зборцы выключана).
- Фіксуецца **час нашага выкліку** `requestReview()`, а не паказ або ацэнка:
  сістэма гэтага не паведамляе.
- Ручная спасылка заўсёды `openStoreListing`, ніколі `requestReview`, і не
  залежыць ад выключальніка.
- Няма апытання «Вам падабаецца?», няма ўласных зорак, няма фільтрацыі.

## Што яшчэ не гатова (блокеры)

- **iOS**: ручная спасылка патрабуе лікавы App Store ID. Перадаецца пры зборцы
  `--dart-define=APP_STORE_ID=<лік>`. Пакуль ID пусты, на iOS паказваецца
  «Не атрымалася адкрыць краму».
- **Android**: спасылка вядзе на `applicationId` усталяванай зборкі
  (тэставая `by.mybrev.playtest2026`); даступнасць карткі ў Google Play трэба
  праверыць у тэстара.
- Рэальнае акно Google Play In-App Review праверыцца толькі праз Play alpha /
  internal app sharing; sideload APK правярае толькі UI.
- Опрос 1–5 і серверны кантракт: не рабілася.

## Як правяраць

```bash
export PATH=$HOME/.cache/flutter-3.41.4/bin:$PATH
flutter test test/review
```

`APP_REVIEW_QA` дазволены толькі ў debug-зборках і зараз выкарыстоўваецца
толькі для `AppReviewController.debugReset()`.
Ручны чэк-ліст: налады → «Ацаніць дадатак» пад «Зваротная сувязь»; пераключальнік
уключаецца/выключаецца і перажывае перазапуск; святло/цемра/марыйская тэмы;
тэкст 200 %; на iOS без `APP_STORE_ID` паказваецца спакойнае ўбудаванае паведамленне пра
памылку.
