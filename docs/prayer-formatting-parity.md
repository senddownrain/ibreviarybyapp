# Форматирование молитв во Flutter — контракт 1.0

Дата проверки: 2026-10-13. База: `origin/main` (`be276b8148a1eb30f9795e76ba9c9499ea9a9ec3`). Ветка: `codex/prayer-formatting`.

## Реализация

- Собственный минимальный конвертер заменён разбором CommonMark AST из `markdown` 7.3.1, с расширениями для одиночных переносов и `:::rubric`.
- В обычных абзацах выделяется только метка К./С./Н./Д./Л./Ц./V./R. (в том числе с наследуемым двоеточием). Цвет рубрик и жирность наследуют размер читательского шрифта. Пунктуация и слова остаются в исходном тексте; авторские выделения слов сохраняются.
- Цитаты, рубрики, заголовки, списки, код, ссылки, явно оформленные метки и неоднозначные инициалы исключены из распознавания ролей. Латинские двойники кириллицы не приравниваются автоматически.
- Заголовки h1–h6, абзацы, вложенные списки, курсив/жирность, код и ссылки, включая reference links, разбираются парсером. Blockquote получает отступ и границу, без буквального `>`; исходный `>` не удаляется из модели.
- Сырой HTML в каноническом Markdown экранируется. Общий DOM-санитайзер очищает наследуемый HTML и URL: опасные схемы, события, script/style/iframe/object и сетевые изображения не попадают в виджет. Представление старых текстовых HTML-документов сохраняется.
- Экран обычной молитвы и предпросмотр локального редактора используют `PrayerContent` и одинаковые темы/стили/размер шрифта. `SelectionArea` позволяет выделять текст вместе с метками; метки не скрываются от доступности.
- Ссылки `/prayer/<id>` используют существующую навигацию. Тесты проверяют открытие, возврат, отсутствующий ID и отказ в доступе к закрытой молитве. Политика прямых/унаследованных ограничений и protected provider не менялись.
- Месса явно отключает общую разметку участников и продолжает использовать `mass_semantics.dart`. Регрессионные проверки BE/LA/EN, рубрик, диалогов, языков и разделов сохраняют прежние ожидания.
- Доставка bundle/overlay, идентификаторы, Firestore, contentManifest, опубликованный контент и веб-репозиторий не изменялись.

## Сверка с вебом

Базовый [контракт 1.0](https://github.com/senddownrain/mybrev/blob/8b02183667490ac50bb9982652512bdfc543a7aa/docs/prayer-formatting-standard.md) и его файл в `main` имеют одинаковый Git blob `f38c08df99459f02b65971e991210ac1121fad93`. PR #121 уже MERGED. Веб-реализация по этому immutable ref использует bare prefixes; общие фиксированные примеры перенесены в Dart-тесты.

В соседнем локальном веб-checkout обнаружены незакоммиченные `prayerLegacyFormatting.js` и изменения `prayerMarkdown.js`, расширяющие отображение меток, обёрнутых в Markdown, и отдельных наследуемых строк. Это расходится с исключением `**С.**` базового контракта. Во Flutter расширение не добавлялось без согласования. Для разработки не требуется ожидать массовой миграции; перед релизом нужно согласовать итоговый синтаксис и повторить сверку с опубликованным контрактом. Flutter читает нормализованные bare labels без новой миграции базы.

«Анёл Панскі» не найден по названию в доступном встроенном наборе. Подлинный источник этой молитвы не подменялся выдуманным. Отдельные контрольные кейсы проверяют настоящую цитату, ошибочно импортированную реплику с `>` (остаётся цитатой) и экранированный литеральный `\>`.

## Проверки и ограничения

Состояния widget-тестов: 320 × 760, light/dark, читательский шрифт 16 и 28.8; роли/рубрики/цитаты, прокрутка, навигация, копируемый RichText, одинаковый предпросмотр. Реальные публичные короткая молитва и «Літанія да святога Арханёла Міхала» проверены из существующего bundle без Firebase и без записи в хранилище.

Chrome 155.0.8059.40 доступен в `flutter devices`. Изолированное Flutter-приложение запускается через `flutter run -d chrome -t tool/prayer_formatting_smoke.dart --web-port 5237`. Визуальный smoke **не выполнен**: Computer Use остановился, не сумев надёжно определить URL окна Windows. Скриншоты не получены. Альтернатива `flutter test --platform chrome test/prayer_formatting_widget_test.dart` скомпилировалась после исправления пути тестового fixture, но зависла на загрузке suite; запуск прерван, прохождение не заявляется.

Первый запуск smoke harness выявил отсутствие Overlay у toolbar в MaterialApp.builder; оболочка перенесена в ShellRoute. Исправленный harness проверяется widget-тестом (чтение, тема, ширина и предпросмотр). Визуальный запуск исправленной версии остаётся обязательным перед готовностью UI.

Native smoke не выполнялся: правка касается общего UI/парсера, не нативных API. Android/iOS smoke нужен перед мобильным релизом. Chrome не заменяет нативную проверку.

## Воспроизведение визуальной проверки

1. `flutter devices`, затем `flutter run -d chrome -t tool/prayer_formatting_smoke.dart`.
2. Проверить контрольную молитву, короткую молитву и длинную литанию из списка bundled public prayers. Harness использует реальные экраны, публичный bundle и memory-only providers, без подключения к Firebase/Hive.
3. Кнопки Theme/320px переключают тему и ширину; штатный Aa читателя изменяет размер шрифта. Проверить 16 и 180%, переносы меток, рубрик, цитат, длинной литании и прокрутку.
4. Проверить ссылки «Іншая малітва», «Няма малітвы», «Закрытая малітва» и возврат. Кнопки Preview/Legacy открывают локальную форму и старый HTML; в форме переключить «Прагляд». Выделить и скопировать текст с меткой.
5. Сохранить скриншоты light/dark, 320px/крупный шрифт и предпросмотра; записать реальные результаты. Подтвердить источник «Анёл Панскі» отдельно с владельцем веб-автофикса.

Постоянная стратегия закреплена в [AGENTS.md](../AGENTS.md), ссылка на неё добавлена в [README.md](../README.md). Существующий `run_in_chrome.bat` сохранён.
