## Integration and validation gates

1. Rebase the 4B branch after Phase 3B, inspect the production diff for each affected reader and refresh audit evidence. Bottom controls, TopChrome, search, navigation, routes and saved positions are integration constraints, not 4B redesign scope.
2. For each commit, inspect real-content before/after screenshots at 320/390/700 in light/dark and the extreme Aa/system combinations. Include one short Prayer, long Belarusian title, every distinct Hours visual pattern, Mass dialogue/rubric, Bible selected verse, Compendium question/part, and Song chords on/off and side/above fallback.
3. Run targeted widget tests for geometry/semantics, existing reader/navigation tests, `flutter analyze`, and device QA on iOS and Android before merging. Widget mock passes cannot certify production HTML, platform safe areas or screen-reader output. Log unverified cases explicitly; do not silently lower Aa or change source text.
4. Keep each commit reversible. If a shared primitive requires domain conditionals for unrelated structures, leave those structures local and record the exception in the audit instead of expanding a universal component.
