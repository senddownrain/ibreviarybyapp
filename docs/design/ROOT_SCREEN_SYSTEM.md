# Phase 3A — единый язык четырёх корневых экранов

Статус: целевая композиция для Phase 3B, без изменения production UI.
Основа — [Quiet Book](DESIGN_CONCEPT.md), [Design System](DESIGN_SYSTEM.md) и
[Top Chrome audit](TOP_CHROME_AUDIT.md). Текущая реализация проверена на
`main @ ad437ff` 2 октября 2026. Нижняя зона может измениться в Phase 2B.

## Общая анатомия

1. **Безопасный верх и тихое управление.** У branch root — Menu, у дочерней
   книги — Back. Действия не заменяют название раздела.
2. **Название страницы.** Літургія, Чытанні, Малітоўнік, Біблія имеют одну
   роль `type.pageTitle`: Cormorant Garamond, baseline 32–34, без огромного
   hero и uppercase. На reader root заголовок книги и название читаемого
   документа не превращаются в два одинаковых крупных титула.
3. **Короткий контекст.** Дата/празднование для двух дневных веток, shelf
   cue для Малітоўніка, книга/перевод/глава для Бібліі. Это системная
   metadata или документный subtitle по смыслу, не рекламный слоган.
4. **Первый осмысленный вход.** Текущий день и часы, чтения выбранного дня,
   полка книг, последняя позиция Бібліі. Он виден без поиска по dashboard.
5. **Основное содержание.** Непрозрачная спокойная page/list surface,
   одинаковые gutter и ритм section/row, но собственная структура каждой
   книги. Следующий экран считывается из подписи строки, а не цвета иконки.
6. **Вторичные возможности.** Альтернативы, категории, favorites, recent,
   scope search доступны после основного входа. Global dock остаётся
   навигацией между четырьмя ветками и не дублируется локальными tabs.

Общая композиция — page title → текущий контекст → главное содержимое →
вторичное. Это принцип порядка, а не жёсткий template: Чытанні и Біблія уже
являются root readers, поэтому документ начинается сразу после компактного
контекста. На всех корнях page title отделён от плавающего chrome.

## Четыре выражения одной системы

| Ветка | Первый блок / главное действие | Содержание | Вторичное |
| --- | --- | --- | --- |
| **Літургія** `/hours` | Выбранный день с явным «Сёння» только для сегодняшней даты; открыть нужный час | Список часов в принятом порядке и доступности, различимые группы без новой рекомендации «что молиться сейчас» | Выбор даты, празднования и альтернатив; связь с Чытаннямі |
| **Чытанні** `/readings` | Та же выбранная дата и литургический контекст; начать чтение | Сам документ и его разделы; cycle/alternative видны как контекст, не как второй большой заголовок | Смена даты, варианта и переход из Ora с сохранением return token |
| **Малітоўнік** `/prayers` | Библиотечная полка: Малітвы, Святая Імша, Спеўнік, Катэхізіс/Кампендый, Сакрамэнты | Группы «на полке», избранное и личные молитвы; единый тип строк/tiles, без второго tab bar | Вход в Library Search с будущими scope `Малітвы · Спеўнік · Катэхізіс`, категории и управление |
| **Біблія** `/bible` | Продолжить с сохранённой книги/главы; явный вход в picker | Текущая глава остаётся читательской страницей; book/chapter и перевод — документный контекст | Search, recent/favorites только если подтверждены данными; не создавать их как пустое обещание |

Літургія и Чытанні — две формы одного литургического дня. Они показывают одну
понятную дату и празднование, но не копируют layout: часы — список входов,
Чытанні — непрерывное чтение. Изменение даты и выбор альтернатив используют
существующую calendar/navigation logic. Переход Ora → Чытанні остаётся явным,
с возвратом к исходному часу.

Малітоўнік — библиотека, а не каталог вкладок. Сегодня production показывает
избранное перед разделами и отдельный prayer-only search icon. Прототип
проверяет более читаемый вход через полку и видимое место поиска. После Phase 2B
имя, scope и endpoint поиска берутся из фактического Library Search; Phase 3A
не меняет его код. Сакрамэнты маркируются как недоступный/будущий раздел, пока
там placeholder, и не выглядят доступной книгой с готовым содержимым.

Біблія не обязана копировать полку. Сейчас `/bible` разрешает сохранённую
позицию и отображает `BibleChapterScreen`. Его title tap открывает выбор
книги/главы; bottom current chapter ведёт туда же. В новом root языке этот
выбор остаётся одной функцией с двумя входами. Повторный блок «працягнуць»
не должен обещать другую позицию, когда читатель уже находится в последней
главе; в прототипе это поясняющий макет, а не новая navigation architecture.

## Ритм, цвет и platform expression

Корни используют общий gutter по Design System: 16 при ширине <360, 20 на
телефоне от 360, 24 от 600. Page title занимает свой спокойный уровень;
заголовки групп и UI-строки — системный шрифт, длинное содержание reader —
Literata или выбранная reader-family. Системный text scale действует на title,
UI и документ по существующему контракту, Aa — только на reader content.
Строки и action targets растут по содержимому; 48 dp — минимум, не потолок.

Литургический цвет — ribbon у даты/празднования и семантических элементов
документа. Он не красит всю страницу, tab dock или Settings. Для Малітоўніка
и Бібліі neutral page показывает принадлежность тому же приложению без
ложного литургического кода. iOS может применять лёгкий glass только к chrome,
Android — Material tonal surface; порядок информации и действия совпадают.

Global dock имеет четыре ветки и один owner на экран. Root layout оставляет
контенту место до последней строки с учетом актуальной высоты нижнего owner.
Чытанні и Біблія сохраняют reader-specific нижнее поведение после Phase 2B;
эта спецификация задаёт отношение к корню, но не геометрию нижних controls.

## Что проверяет lab

При `--dart-define=IBREVIARY_TOP_CHROME_LAB=true` открыть прямой route
`/design/top-chrome-lab` (в web: `/#/design/top-chrome-lab`). Режим
«Чатыры карані» показывает одинаковую анатомию всех веток. Отдельные сценарии
показывают Ora, Prayer, Bible и Mass reader. A — плавающий тихий ряд;
B — выделенный компактный ряд; C — схлопывание actions по ширине.
Переключатели ширины 320/360/390/700, system 100/150/200%, Android/iOS и
длинного заголовка выявляют конкуренцию title/actions. Макеты содержат только
пример текста. Нажатие action показывает label; ни одно действие не вызывает
production navigation или запись данных.

Критерий выбора композиции для Phase 3B: все четыре корня ощущаются одной
книгой, у reader есть доступное Aa, Menu и Back легко различимы, title и первый
абзац не перекрыты, overflow не скрывает обязательное действие. Вариант C
может стать правилом адаптации A или B, а не отдельным дизайном. Окончательное
решение следует принять после визуальной проверки на устройствах и повторной
сверки нижней зоны по завершении Phase 2B.
