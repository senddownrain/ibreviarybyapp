# Тексты в приложении: «офлайн с установки»

> Вторая итерация (октябрь 2026). Первая сделала чтение cache-first, индексы,
> вычисляемый календарь и единые компоненты загрузки; она осталась
> ориентированной на «окно дней» и синхронизацию групп. Эта итерация меняет
> саму модель: **тексты входят в приложение**, сеть только обновляет их.

```text
Я устанавливаю молитвенное приложение — и тексты просто есть.
```

## Stage A — аудит и решение

### Что было

```text
установка → почти пустой Hive
  → день открыт → запросы Firestore по дате/празднику/периоду (Source.server)
  → фон: окно ±7 дней, затем группы «Малітвы / Біблія / Астатняе / Спеўнік / Кампендый»
  → Налады: автообновление, «бліжэйшыя дні», «толькі па Wi-Fi», перыяд, «Загрузіць усю базу»
```

- `days` и `readings` загружались по датам (`CacheWarmupService`), с отметками
  `ready_*`, `fullCache_*`, `lastSync_*`, `bytes_*`, `warmupFrom/To`.
- Дата за пределами окна (через три месяца, следующий год) — сетевая операция;
  без сети — «Не ўдалося загрузіць дзень».
- Hive открывал все боксы целиком в память: у пользователя «всей базы» это
  ~59 МБ JSON-объектов в RAM.
- `LoadState`/`LoadPhase` и `DataActivity` были определены и протестированы, но
  экраны жили своими `_loading`/`FutureBuilder` — две параллельные системы.
- Библия уже была в приложении, но `SyncTarget` Библии оставался; Кампендый уже
  работал по правильной схеме (bundle + meta-проверка + валидация).

### Замеры корпуса

Источник: локальный snapshot Firestore (2026-10-05, `days`, `readings`,
`liturgicalTemplates`, `invitatoriums`, `completoriums`) и отдельный экспорт
`prayers`, `prayerCategories`, `songs`, `compendium` (2026-10-06). Форма —
та, что хранит приложение (Timestamp → мс).

| Коллекция | Документов | JSON | gzip -9 | brotli 11 / xz | **строки один раз + gzip** |
|---|---:|---:|---:|---:|---:|
| days | 735 | 51.4 МБ | 8.78 МБ | 1.34 / 1.27 МБ | **2.19 МБ** |
| readings | 815 | 4.3 МБ | 0.93 МБ | 0.45 МБ | **0.82 МБ** |
| liturgicalTemplates | 16 | 1.06 МБ | 0.17 МБ | 0.11 МБ | **0.16 МБ** |
| completoriums | 35 | 0.31 МБ | 0.04 МБ | 0.01 МБ | **0.01 МБ** |
| invitatoriums | 4 | 0.01 МБ | — | — | **<0.01 МБ** |
| prayers | 117 | 1.99 МБ | 0.27 МБ | 0.17 МБ | **0.24 МБ** |
| prayerCategories | 5 | <0.01 МБ | — | — | **<0.01 МБ** |
| songs | 447 | 0.35 МБ | 0.10 МБ | 0.08 МБ | **0.11 МБ** |
| **Всё** | **2 174** | **59 МБ** | **10.2 МБ** | **2.1 МБ** | **3.53 МБ** |

`days` огромен только в сыром виде: одни и те же псалмы и гимны повторяются в
сотнях дней. gzip (окно 32 КБ) этого не видит; таблица уникальных строк
(39 234 длинные строки → 6 363 уникальные) убирает повтор, и обычного gzip,
который уже декодирует приложение (`archive`), хватает. xz/brotli дали бы ещё
~1 МБ, но потребовали бы чистого Dart-декодера xz/brotli — медленнее и без
надобности.

Для сравнения: Біблія bel 1.76 МБ, ru 1.68 МБ, Кампендый 0.12 МБ.

### Release-сборки (до → после)

| Артефакт | До | После | Разница |
|---|---:|---:|---:|
| APK arm64-v8a (≈ загрузка из Google Play) | 28.56 МБ | 32.03 МБ | **+3.47 МБ** |
| APK armeabi-v7a | 26.68 МБ | 30.11 МБ | +3.43 МБ |
| iOS `Runner.app` | 166.24 МБ | 169.41 МБ | +3.17 МБ |
| iOS `Runner.app`, zip (≈ App Store) | 68.41 МБ | 71.95 МБ | **+3.54 МБ** |

Локальный `flutter build appbundle` не отрезал символы нативных библиотек
(тулчейн), поэтому AAB для сравнения не годится; APK под одну ABI — честная
оценка загрузки. IPA с подписью — на Codemagic.

Ассеты лежат в пакете уже сжатыми и не распаковываются на диск: установленный
размер растёт на те же ~3.5 МБ. Hive после установки содержит **0 байт**
контента.

### Четыре модели

| | A. Окно дат (было) | B. Bundle → импорт в Hive | **C. Bundle + слой обновлений** | D. Готовые Hive-файлы в ассетах |
|---|---|---|---|---|
| Первый запуск без сети | только вычисляемый календарь | всё, после импорта | **всё, сразу** | всё, после копирования |
| Работа на первом запуске | сеть для каждого дня | импорт ~59 МБ в Hive (секунды, блокирует) | **декод 3.5 МБ в isolate (~0.15 с на хосте)** | копирование ~60 МБ |
| Диск | до 59 МБ Hive | 3.5 МБ ассет + ~60 МБ Hive | **3.5 МБ ассет + только изменения** | 60 МБ ассет + 60 МБ копия |
| RAM | Hive-боксы целиком | Hive-боксы целиком (~59 МБ JSON) | **уникальные строки один раз** | как B |
| Обновления | перекачка дат/групп | патчи в Hive | **документы по хешам** | как B |
| Сложность | очередь, окна, группы, политика Wi-Fi | импорт + миграции схем | **слияние baseline+overlay в одном классе** | формат Hive между версиями, адаптеры, копия на iOS/Android, восстановление |
| Риск | «нет дня» без сети | долгий первый запуск | слой слияния | несовместимость файлов Hive между версиями |

**Решение: модель C.** B и D хранят корпус дважды и держат его в Hive
(а значит в RAM) целиком; D к тому же привязывает ассет к бинарному формату
Hive. В C читатель с первого запуска имеет всё, Hive содержит только то, что
изменилось после сборки приложения, а слияние — один класс
(`ContentCollection`) с тем же API, что Hive-бокс (`get/keys/values/length`),
поэтому код поиска дня и чтений не менялся по сути.

Гипотеза «офлайн с установки» подтвердилась замером: весь корпус добавляет к
пакету столько же, сколько один перевод Библии.

### Что стало лишним

| Было | Стало |
|---|---|
| «Аўтаматычнае абнаўленне» | проверка раз в сутки всегда: один маленький документ |
| «Рыхтаваць бліжэйшыя дні», окно ±7, «Назад/Наперад ад сёння» | все даты локальные |
| «Вялікія абнаўленні толькі па Wi-Fi» (постоянный переключатель) | вопрос один раз, когда большое обновление реально есть на мобильной сети |
| «Даныя праграмы», группы «Літургія і чытанні / Малітвы / Біблія / Спеўнік / Кампендый / Астатняе», «Перыяд», «Загрузіць усю базу», счётчики документов, размеры кэша, «Спыніць загрузку» | удалены |
| «Ачысціць загружаныя тэксты» | удалено: удалять нечего, тексты в приложении |
| пункт меню «Сінхранізацыя», подсказки «сінхранізуйце ў Наладах» | удалены |
| `SyncTarget`, `SyncPlan`, `SyncStatusNotifier`, `CachePolicy`, `CacheWarmupService`, `DayPrefetchService`, `LiturgicalDayService` и `StaticLiturgicalService` (сетевые пути), `CacheStats`, `DataBootstrapNotifier`, `DataActivity`, `LoadState`, `AppOfflineNotice`, `songs_seed.json`, синхронизация Библии | удалены |

### Риски миграции (и что сделано)

- **Удалить новее, чем bundle.** Документ старого кэша сохраняется, если его
  собственный `updatedAt`/`importedAt` позже, чем у документа в bundle, и текст
  отличается (хеш). Следующая проверка сверяет его с манифестом.
- **Прервать на середине.** Боксы удаляются только после чтения, флаг
  `contentModel = 2` пишется последним; повторный запуск — та же работа.
- **Задеть данные читателя.** `settings` (налады, выделения, избранное),
  `localPrayers` не трогаются. Удаляются только канонические копии, индекс
  чтений, `yearOptions`, скачанные копии Библии и метки старого кэша.
- **Большой старый бокс в RAM.** Миграция идёт через 2 с после старта, после
  первого экрана, один раз.

## Stage B — архитектура

```text
                    ┌──────────── пакет приложения (read-only) ────────────┐
                    │ assets/content/<collection>.json.gz  + manifest.json │
                    │ assets/bible_seed_*.json.gz, assets/compendium/…     │
                    └───────────────┬──────────────────────────────────────┘
                                    │ декод в isolate, лениво, литургия первой
                                    ▼
   Hive content_<collection>  ──▶  ContentStore / ContentCollection  ◀── вычисляется:
   (только новее bundle:            baseline ⊕ overlay = текст          календарь, Пасха,
    {d, h, v} или удаление)         get · keys · values · digest        периоды, недели
            ▲                                │
            │ активировать всё сразу         ▼
   ContentUpdater ── проверка хешей    DaysIndex · ReadingsIndex (в памяти)
            ▲                                │
            │ только изменённые id           ▼
   Firestore contentManifest/current   LiturgicalContentService · ParsedReadingsService
            contentManifest/<c>        (синхронно; дата = поиск, не загрузка)
            <c>/<id>                         │
                                             ▼
                                Гадзіны · Чытанні · Малітоўнік · Спеўнік
```

### 1. Что входит в приложение

`assets/content/`: `days`, `readings`, `liturgicalTemplates`, `invitatoriums`,
`completoriums`, `prayers`, `prayerCategories`, `songs` (3.53 МБ), плюс
`manifest.json` (дата контента, число документов и digest каждой коллекции).
Отдельно, как и раньше: Біблія (bel, ru), Кампендый, чин Імшы, шрифты.

Формат файла коллекции: `{schemaVersion, collection, contentVersion, strings,
docs, hashes}`; строка ≥ 32 символов хранится один раз в `strings`, в
документе — ссылка `"\u0001<индекс>"`. Декодер — `decodeContentCollection`
(`compute`, вне UI isolate); документы разделяют одни и те же объекты String.

Собирает MyBrev: `npm run content:app-bundle -- --snapshot … --out
<flutter>/assets/content` (только из локального snapshot).

### 2. Что лежит в Hive

| Бокс | Что |
|---|---|
| `content_<collection>` | только документы, изменённые после сборки приложения: `{d: документ, h: хеш, v: версия}` или удаление `{x: true}` |
| `settings` | налады, выделения, избранное |
| `localPrayers` | свои малітвы |
| `meta` | `contentModel`, `contentLastCheck`, `contentLastUpdate`, `contentUpdateVersion` |
| `compendium` | более новая проверенная копия Кампендыя, если скачана |

### 3. Что вычисляется

Параметры года, Пасха и подвижные праздники, периоды и недели, псалтырь
(`computeYearOptions`, `CalendarService`, `computeLiturgicalContext`).
Арифметика дат — календарными днями (`lib/utils/civil_date.dart`):
`Duration(days: n)` и `difference().inDays` на переходе на летнее время в ЕС
давали соседний день (Пальмовая нядзеля 2026 — 29 марта, день перехода).

### 4. Что скачивается

Только изменения: документ `contentManifest/current` (~1 КБ), при отличии
digest — `contentManifest/<collection>` (хеши, ~30–40 КБ), затем изменённые
документы по id (`whereIn`, по 30). Кампендый — своей meta-проверкой.

### 5. Когда используется сеть

- раз в сутки: через 5 с после старта и при возвращении в приложение
  (`ContentUpdateScheduler`), а также при появлении сети, если проверка давно
  не делалась;
- по кнопке «Праверыць абнаўленні».

Открытие дня, чтений, молитв, песен, Библии, Кампендыя сеть не использует.

### 6. Как сравниваются версии

Хеш документа — sha256 (16 hex) канонического JSON без служебных полей
(`updatedAt`, `importedAt`, `parsedAt`, `miniSavedAt`); одинаково считается в
Node (`scripts/content/lib/app-content.mjs`) и Dart (`documentHash`) — проверено
на всех 2 174 документах. Digest коллекции — sha256 строк `id\thash\n` по
порядку id. Устройство считает digest своего итогового содержимого
(bundle ⊕ overlay): совпал с манифестом — ничего не делаем; нет — сравниваем
хеши по id и качаем только отличающиеся.

### 7. Как обновление становится активным

```text
скачать изменённые документы
→ каждый: есть? хеш совпадает с манифестом?   нет → отклонить всё (ContentUpdateRejected)
→ все проверены → записать в overlay (putAll) и удаления
→ revision++ → индексы и экраны перестраиваются
```

Отказ, обрыв сети, несоответствие — текущие тексты остаются. Запись по
документу атомарна и несёт свой хеш, поэтому прерванная активация
доделывается следующей проверкой. Большое обновление (> 5 МБ) на мобильной
сети ждёт решения читателя.

### 8. Что происходит без сети

Ничего не меняется: все тексты на устройстве. В Наладах — «Няма сеткі. Усе
тэксты працуюць і так.», кнопка проверки неактивна. Экранов «нет сети» и
плашки «працуем з захаванымі данымі» больше нет.

### 9. Что контролирует читатель

Налады → «Даныя і афлайн»:

```text
✓ Тэксты даступныя без сеткі
  Літургія гадзін, чытанні, малітвы, Біблія, спеўнік і Кампендый уваходзяць у праграму.

Абнаўленні тэкстаў
Тэксты актуальныя · праверана сёння, 09:42
Тэксты ад 6 кастрычніка 2026
[ Праверыць абнаўленні ]
```

Только если большое обновление есть, а сеть мобильная:

```text
Даступна абнаўленне · 18.0 МБ
Вы выкарыстоўваеце мабільную сетку.
[ Загрузіць 18.0 МБ ]
  Пачакаць Wi‑Fi
```

Постоянного переключателя Wi-Fi нет: обычная проверка — один маленький
документ, обычное обновление — десятки килобайт; спрашивать надо только о
реально большом, и только в момент, когда оно есть. «Пачакаць Wi‑Fi»
продолжает само, когда появляется Wi-Fi. Размеры показываются только в этом
вопросе.

### 10. Свежая установка

Всё доступно сразу и без сети: Літургія гадзін и чытанні на любую дату
(вычисляемый календарь + полный корпус), заклік, камплета, Commons, малітвы,
катэгорыі, спеўнік, Біблія, Кампендый. Первое открытие дня ждёт декодирования
литургических коллекций (≈ 0.15 с на хосте; на телефоне — оценка 0.3–0.7 с,
нужно измерить), остальные коллекции декодируются следом в фоне.

### 11. После обновления из App Store / Google Play

Новый bundle сравнивается со слоем обновлений при декодировании
(`_reconcileWithBaseline`): запись overlay удаляется, если в bundle тот же хеш
или bundle не старее записи (`v ≤ contentVersion` bundle). Более новые
обновления остаются. Схема контента (`schemaVersion`) выше поддерживаемой —
манифест игнорируется до обновления приложения.

### 12. Миграция существующих пользователей

`ContentMigration` (один раз, через 2 с после старта): см. «Риски миграции»
выше. Перенесённые документы получают свой хеш; если на сервере тот же текст,
скачивать ничего не придётся.

### Состояния экранов

| Состояние | Что видно |
|---|---|
| тексты декодируются (только при запуске) | тихий контур текста `AppLoadingState` / `DataLoadingNotice` («Адкрываем …») |
| готово | текст сразу, в том же кадре |
| обновление контента | текст остаётся; в Наладах — линия `AppRefreshBar` (2 px) |
| нет сети | ничего не меняется |
| не удалось открыть тексты (повреждённый пакет) | `AppErrorState` + «Паўтарыць» |
| у даты нет текстов | спокойное сообщение «Для гэтай даты тэксты адсутнічаюць» |

`LoadState` и `DataActivity` удалены: при локальном контенте у экранов нет
фаз «обновление/офлайн/частично», а единственное асинхронное ожидание —
`liturgicalContentReadyProvider` / `ContentStore.ensureLoaded`. Устаревший
запрос другой даты не перезаписывает экран (`_loadGeneration` в Чытаннях,
у Гадзін каждый день и час — свой экран со своим `Future`).

### Публикация (MyBrev)

| Когда | Команда |
|---|---|
| изменён контент в Firestore (импорт, правка в админке) | `npm run content:manifest` (dry-run) → `npm run content:manifest -- --apply` |
| перед релизом приложения | обновить snapshot → `npm run content:app-bundle -- --snapshot … --out …/assets/content` |

Пока манифест не перепубликован, правка в Firestore до приложений не дойдёт
(хеш документа не совпадёт с манифестом, обновление будет отклонено целиком).

| Операция | Время |

декодирования и JIT; удерживаемую кучу на устройстве нужно измерить
(DevTools). Прежняя модель держала в RAM открытые боксы Hive целиком.
