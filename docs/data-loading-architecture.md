# Загрузка данных: архитектура, состояния и UI

Дополняет `docs/offline-sync.md` (группы синхронизации, постраничная загрузка,
отметки готовности дат — там без изменений).

Главное правило: **всё, что уже есть на устройстве, показывается сразу; сеть
обновляет данные, а не является условием показа экрана.**

## Current state (до изменений)

```text
Экран → сервис (создаётся заново) → Hive → Firestore (Source.server)
```

- Hive: `days`, `readings` (+ `readingsIndex`), `prayers`, `yearOptions`,
  `invitatoriums`, `completoriums`, `settings`, `meta` (отметки `ready_*`,
  `fullCache_*`, `lastSync_*`, размеры).
- `selectedDateReadyProvider` — foreground-загрузка выбранной даты;
  `DataBootstrapNotifier` — старт и фоновое окно ±7 дней через очередь
  `SyncStatusNotifier`; `CacheWarmupService` — загрузка одной даты.
- Экраны Гадзіны/Чытанні сами создавали `CalendarService`,
  `LiturgicalDayService`, `ParsedReadingsService` и ждали `Future`.

## Problems (найдено аудитом)

| # | Проблема | Следствие |
|---|---|---|
| 1 | Календарь зависел от Firestore `yearOptions` | первый запуск без сети — пустой календарь; каждый экран ждал `ensureYearOptions` |
| 2 | Поиск дня по дате/празднику/периоду — полный обход `days` с копированием каждого документа, 2–3 раза на дату, на UI isolate | лишняя работа при каждой смене даты и при каждом `cacheEpoch` |
| 3 | Чтение чтений из кэша — индекс **и** полный обход `readings` с копированием | то же для чтений |
| 4 | `OraScreen` / `HoraPickerScreen` всегда шли через `FutureBuilder`/`async` | кадр «Загружаем…» + shimmer даже когда всё в кэше |
| 5 | `ReadingsScreen._load` всегда ставил `_loading = true` и ждал 32 мс | текст исчезал и мигал при каждой смене даты |
| 6 | Нешпары ждали сеть ради завтрашнего дня | блокировка экрана из-за второстепенного запроса |
| 7 | Одна дата могла запрашиваться параллельно (выбранная дата, Нешпары, фоновое окно) | дублирующие запросы |
| 8 | `markDateCached` писал на диск при каждом выборе уже готовой даты | лишние записи |
| 9 | Движимые даты считались через `Duration(days: n)` | на границе перехода на летнее время Пальмовая нядзеля «уезжала» на день (в ЕС; в Беларуси перехода нет) |
| 10 | Ошибка загрузки другой даты показывалась как «Няма даступнага літургічнага дня» | нет кнопки «Паўтарыць» |
| 11 | Loader показывал «У кэшы: 3.4 МБ», «запытваем з сервера» | технический язык на экране чтения |
| 12 | Настройки: шесть технических групп сразу | раздел выглядел как debug-панель |

## Proposed architecture

```text
Экран
  ↓  синхронно: «что есть на устройстве?»      → показать сразу
  ↓  только при промахе: Future                 → loader / ошибка
Сервис чтения (LiturgicalContentService, ParsedReadingsService)
  ↓
Память: computeYearOptions (memo), DaysIndex, ReadingsIndex
  ↓
Hive (days, readings, …, отметки готовности дат)
  ↓
CacheWarmupService.warmupDate  — один запрос на дату (dedupe)
  ↓
Firestore
```

Новый фреймворк и зависимости не добавлялись: Riverpod + Hive остались.

| Слой | Файл | Роль |
|---|---|---|
| Календарь | `lib/utils/computed_year_options.dart`, `CalendarService` | год вычисляется на устройстве (computus), синхронно, для любого года |
| Индекс дней | `lib/services/days_index.dart` | `_date` / `_feast` / период → id документа; перестраивается лениво после записи в box |
| Локальное чтение | `LiturgicalContentService.resolveDayLocal`, `ParsedReadingsService.cachedForDate` | синхронный результат или `null` (промах) |
| Загрузка даты | `CacheWarmupService.warmupDate` | общий `_inFlight`: одна дата — один запрос |
| Состояние | `lib/models/load_state.dart` | `LoadPhase`, `LoadState<T>` |
| Активность | `lib/providers/data_activity_provider.dart` | page / refresh / prefetch / global |
| Диагностика | `lib/services/data_log.dart` | `CACHE HIT`, `CACHE MISS`, `FETCH START/END`, `PREFETCH`, `STALE DATA`, `NETWORK ERROR` — только в debug, в release вырезается `assert` |

### Классы данных

| Класс | Примеры | Стратегия |
|---|---|---|
| A. Статические | заклік, камплета, малітвы, убудаваная Біблія | Hive; обновление не чаще раза в сутки в фоне |
| B. Год | anchors года, движимые праздники | **вычисляются**, сеть не нужна |
| C. Дата | часы, чтения | cache-first + отметка готовности даты + prefetch соседей |
| D. Большие базы | Біблія, Спеўнік, Кампендый | bundled seed; обновление вручную или в фоне только по Wi-Fi |

## Loading states

```text
initial → loading ──────────────→ ready ⇄ refreshing
             │                      │         │
             └→ error               └→ offline / partial
```

| Фаза | Что на экране |
|---|---|
| `loading` | данных нет: `AppLoadingState` (единственный случай полноэкранного loader) |
| `ready` | контент |
| `refreshing` | контент **остаётся**, сверху `AppRefreshBar` (2 px, без сдвига layout) |
| `partial` | контент + второстепенный блок не получен |
| `offline` | контент с устройства + `AppOfflineNotice` |
| `error` | данных нет и запрос не удался: `AppErrorState` с «Паўтарыць» |

`loadStateAfterFailure()` гарантирует: неудачный запрос никогда не убирает
контент с экрана.

`DataActivity`: `pageLoading` (день без контента) — единственное состояние,
которое может занять экран. `refreshing`, `backgroundPrefetch`,
`globalUpdate` идут рядом с читаемым контентом.

## Prefetch strategy

| Приоритет | Что | Когда |
|---|---|---|
| critical | выбранная дата | сразу; сеть только если дата не помечена готовой |
| immediately useful | завтра (нужно Нешпарам), вчора | после появления дня на экране, тихо, без UI |
| probable next | окно ±7 дней (настраивается) | фоновая очередь после первого экрана |
| background optional | малітвы, заклік, камплета, категории; Біблія — только Wi-Fi при включённой опции | там же, не чаще раза в сутки |

Запуск не ждёт ничего, кроме открытия Hive и Firebase init. Спеўнік и
Кампендый в автоматическое окно не входят.

## Offline strategy

- Дата помечена готовой → экран строится синхронно, сеть не трогается.
- Нет сети, есть кэш → контент + «Працуем з захаванымі данымі».
- Нет сети и нет данных → `AppErrorState` «Не ўдалося загрузіць дзень» +
  «Паўтарыць»; при возвращении сети загрузка возобновляется сама.
- Календарь доступен всегда (вычисляется).

## Settings UX

Налады → **«Даныя і загрузка»**:

```text
Аўтаматычнае абнаўленне               [ON]
Рыхтаваць бліжэйшыя дні               [ON]
Вялікія абнаўленні толькі па Wi-Fi    [ON]

Даныя для працы без сеткі
Гатовыя для працы
Апошняе абнаўленне: сёння, 12:34
Выкарыстана: 34 МБ

[ Абнавіць даныя ]
Даныя праграмы  ›
```

«Даныя праграмы» (bottom sheet): список «Літургічны каляндар / Літургія
гадзін / Чытанні / Малітвы / Біблія / Спеўнік / Кампендый» со статусом
человеческим языком, затем свёрнутые «Дадатковыя загрузкі» (прежние группы и
«Загрузіць усю базу») и «Ачысціць загружаныя тэксты» (только `days` и
`readings`; налады, свои молитвы и выделения остаются).

Прогресс определённый только когда он реальный (число обработанных групп/дат
из `SyncStatus.progress`); иначе — неопределённая линия. Проценты не
симулируются.

## UI loading language

`lib/widgets/loading/app_load_states.dart`:

| Компонент | Назначение |
|---|---|
| `AppLoadingState` | первый показ: тонкая линия + подпись (+ контур) |
| `AppProgressLine` | линия 2 px; при «reduce motion» неподвижна |
| `AppRefreshBar` | обновление поверх контента, всегда 2 px |
| `AppOfflineNotice` | «Працуем з захаванымі данымі» |
| `AppErrorState` | нет данных + ошибка, кнопка повтора |
| `LoadingPlaceholder` | неподвижный контур текста или списка (без shimmer рядом с литургическим текстом) |

`DataLoadingNotice` оставлен как тонкая обёртка над `AppLoadingState`
(без размеров кэша и слов «сервер»).

## Что не проверено

Изменения проверены `flutter analyze` и `flutter test` (438 тестов). На
устройстве/симуляторе (iOS и Android, light/dark) экраны в этой ветке не
открывались — это нужно сделать перед слиянием.

## Remaining

- `prayers`, `songs`, `compendium` экраны уже cache-first; их loader-ы
  (`LinearProgressIndicator`) на общие компоненты не переводились.
- `OraScreen` при промахе по завтрашнему дню всё ещё ждёт его для Нешпар
  (редко: завтра подгружается заранее).
- `ReadingsIndex` не индексирует `_dayId`; для него остался один проход по
  `readings` без копирования документов.
- Замеры cold/warm start на устройстве не делались.
