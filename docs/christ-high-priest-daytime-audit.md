## Что действительно есть в исходном бандле

`assets/content/days.json.gz`, версия коллекции `1791877243449`: один документ `days/feast-christthehighpriest`, хеш `c62263e79af628b2`, `_rank: festum`. Дата не зашита в документ: календарь выбирает праздник по подвижному правилу. 28.05.2026 — этот праздник во всех четырёх белорусских диоцезах, в том числе Pinsk.

| Поля каждого часа | Состояние исходного bundle | Результат |
| --- | --- | --- |
| `sext1/2/3Hymn` | `null` | Гимн соответствующего текущего часа |
| `sext1/2/3Ps1/2/3` | `null` | Псалмы соответствующего текущего часа |
| `sext1/2/3Ant1` | Три собственных текста, слова совпадают с Web JSON | Сохраняются отдельно |
| `sext1/2/3Ant2/3` | `null` | Пустые: одна антифона вокруг трёх псалмов |
| `sext1R` | Гбр 7, 26–27, собственные К./Н. присутствуют | Сохраняется |
| `sext2R` | 1 П 2, 4–5, собственные К./Н. присутствуют | Сохраняется |
| `sext3R` | 1 П 2, 9–10, собственные К./Н. присутствуют | Сохраняется |
| `sext1/2/3Pr` | Одинаковы с `laudesPr`, полное окончание | Праздничная молитва сохраняется |

Исходный bundle **уже содержит собственные тексты**, включая версикулы/ответы. Утверждать их отсутствие было бы неверно. Отличия от проверенного JSON: HTML-оформление, entities/CRLF и полное окончание молитвы вместо краткого «Праз Пана нашага.». Основная неисправность — `null` гимнов/псалмов перекрывают значения period day при `{...period, ...proper}`; прежний вызов для подвижных праздников не заполняет эти пропуски.

Для 28.05.2026 текущий день — `ordinary-w8-d5`, дополненный псалтирным `ordinary-w4-d5`. Проверки сравнивают все три гимна и все девять псалмов с этим текущим днём, а не с фиксированным общим текстом праздника.

## Исправление Dart и соответствие Web

`liturgical_content_service.dart` теперь вызывает `resolveMovableFeastAgainstPeriod`. Режим `fillMissingDaytime` перенесён из PR #183: только подвижные `festum`/`feast` заполняют пропуски трёх дневных часов; чтения не подставляются из будня при обычном заполнении пропусков, молитва при отсутствии своей берётся из праздничной Ютрані. Существующее разделение `sext1`, `sext2`, `sext3` и совместное использование полей Terce сохраняется. Для старого документа High Priest без ранга разрешён точечный fallback по коду; явная `solemnitas` его блокирует.

Маршруты часов во Flutter: `terz`, `sext`, `non`; последний соответствует Web `none` и полям `sext3*`. Production-маршруты не переименованы; стенд явно учитывает это соответствие.

Дополнительно защищены два случая:

1. Устаревший `_fromDayFields` не уничтожает заполненное собственное дневное поле праздника. Очищенный список сохраняется в результате, чтобы повторное разрешение не вернуло ошибку. Явные маркеры `from-day`, включая HTML/скобки, продолжают разрешаться.
2. При одной собственной антифоне Sext/None пустые Ant2/Ant3 не заимствуются из Terce, даже если там три антифоны.

Остальные часы, фиксированные празднования, подвижные памяти и торжества используют прежние пути сборки. Тест сравнивает все недневные поля High Priest с прежним результатом; отдельные тесты проверяют другие праздники и торжества.

Web PR #183 применяет безусловную JSON-накладку High Priest. Она во Flutter не скопирована: в проверенном исходном бандле уже достаточно собственного текста для полноценной офлайн-молитвы. Поэтому нет дополнительного Dart-перевода, чтения JSON при отображении или второго слоя, который мог бы маскировать будущий контентный патч.

## Доставка установленным приложениям

После повторной проверки план `reports/liturgy/christ-high-priest-daytime-patch.json` сокращён **с 27 до 12 присваиваний** в одном документе. Прежний план был избыточным: он заменял правильные собственные тексты их другим HTML-оформлением и сокращал полное окончание молитвы. Эти 15 присваиваний удалены.

| Что действительно изменяется | Количество | Было → стало |
| --- | --- | --- |
| `sext1Hymn`, `sext2Hymn`, `sext3Hymn` | 3 | `null` → `from-day` |
| `sext1Ps1`, `sext1Ps2`, `sext1Ps3` | 3 | `null` → `from-day` |
| `sext2Ps1`, `sext2Ps2`, `sext2Ps3` | 3 | `null` → `from-day` |
| `sext3Ps1`, `sext3Ps2`, `sext3Ps3` | 3 | `null` → `from-day` |

Все антифоны, чтения вместе с К./Н., `sext1Pr`, `sext2Pr`, `sext3Pr`, `laudesPr` и остальные поля документа сохраняются **побайтово**. В частности, полное окончание «Праз Пана нашага Езуса Хрыста, … Бог, праз усе вякі вечныя. Амэн.» не заменяется кратким «Праз Пана нашага.». Пустые Ant2/Ant3 в хранилище остаются `null`; рендерер показывает их пустыми. `_fromDayFields` патч не переписывает.

План содержит precondition hash `c62263e79af628b2`, новый result hash **`82cc1163da5f1e12`** и только 12 значений `set`. Новый Flutter уже заполняет эти пропуски алгоритмически, но старый Flutter понимает только явные ссылки. Поэтому 12 ссылок нужны для доставки существующим приложениям. Глобальную замену документа применять нельзя: необходимо полевое обновление с проверкой актуального состояния.

Генератор предварительно проверяет три чтения с ответами и три антифоны по Web JSON, а полные молитвы — по праздничной Ютрані и телу проверенной молитвы. Он **отказывает**, если обнаружен неправильный/сокращённый Proper, лишняя антифона, неожиданный заполненный псалом/гимн или stale `_fromDayFields` для собственного текста. Он не исправляет эти случаи автоматически и не расширяет патч. Уже работающие ссылки не переписываются; повторная подготовка после применения даёт ноль изменений.

Воспроизведение подготовки (без Firebase SDK и без сетевых обращений):

```sh
node scripts/prepare_high_priest_daytime_patch.mjs --web ../mybrev
# На предоставленном актуальном локальном snapshot:
node scripts/prepare_high_priest_daytime_patch.mjs --web ../mybrev \
  --snapshot <private-snapshot> --out <private-plan.json>
```

`--apply` намеренно запрещён. План из bundle не удостоверяет live ID/precondition. Перед применением владельцу требуется сверить документ(ы) в актуальном snapshot, согласовать diff, отдельно разрешить полевую Firestore-запись. После записи нужен предусмотренный Web процесс `npm run content:manifest` с вердиктом **SAFE CONTENT PATCH**, затем отдельное разрешение на публикацию `-- --apply`. Никаких override порогов или публикации из этой ветки.

`ContentStore`/`ContentUpdater` не менялись: исходные bytes, hashes и digests bundle сохранены; updater проверяет хеш скачанного документа и атомарно активирует Hive overlay. Неисправный транспорт отвергается целиком. Патч сохраняется при офлайн-перезапуске; последующая исправленная версия имеет приоритет. Следующий согласованный app bundle должен поглотить опубликованный контент обычным release-процессом.

## Визуальная и мобильная приёмка

Изолированный стенд `tool/high_priest_daytime_smoke.dart` использует неизменённый bundle, production router и настоящий `OraScreen`, без Firebase initialization. Команда:

```sh
flutter devices
flutter run -d chrome --no-web-resources-cdn -t tool/high_priest_daytime_smoke.dart \
  --web-port 5240 --web-browser-debug-port 9222
# В другом терминале, с установленным playwright:
FLUTTER_ROOT=<тот-же-sdk> NODE_PATH=<playwright-parent> \
  node scripts/smoke_high_priest_daytime.cjs
```

В среде без дисплея официальный Google Chrome запускается с `--headless --disable-gpu`, **без отключения его sandbox**; через CDP используется именно вкладка Flutter на `http://localhost:5240/`. Engine CanvasKit и fallback Roboto обслуживаются из того же локального Flutter SDK, книжные шрифты — из неизменённых app assets. Внешние сервисы блокируются.

Google Chrome **157.0.8103.38**: **12 состояний, 36 реальных PNG, ошибок Flutter/браузера и неожиданных внешних запросов — 0**. Просмотрены все 36 снимков через три обзорных листа и отдельно ключевые оригиналы чтений, антифон, ответов и конца страницы. Для каждого часа проверены light/dark, ширина 390 dp при обычном шрифте и 320 dp при максимальных **180%** reader font. Видны свои антифоны, правильные отдельные чтения и К./Н.; псалмы восстановлены; молитва и конец страницы достижимы прокруткой. Горизонтального переполнения не обнаружено. Ссылка атрибуции видима в конце; внешний сайт в офлайн-прогоне не открывался. При позиционировании абзаца соседний заголовок иногда оказывается под плавающей панелью — он доступен обратной прокруткой; это существующее поведение reader, не потеря текста.

Это визуальная приёмка исходного исправления PR #63. На этапе минимизации Chrome повторно не запускался: runtime/UI не менялись, а все собственные тексты исходного bundle сохранены. Оставлены прежние 36 снимков; новые проверки охватывают доставку минимального патча на старой и новой версии Flutter.

Перед мобильным релизом требуется отдельный Android/iOS smoke: холодный старт без сети; выбор праздника и всех трёх часов на 28.05.2026/Pinsk и подвижной дате 2027; обновление через настоящий опубликованный манифест, перезапуск и последующая работа офлайн; светлая/тёмная тема, максимальный reader font и системное увеличение, полная прокрутка до К./Н. и молитвы; возврат/смена часа, системные safe areas, TalkBack/VoiceOver и жизненный цикл. Chrome не подтверждает нативные Firebase/Hive-плагины и доставку через магазины. Android/iOS native smoke в этой работе не выполнялся.
