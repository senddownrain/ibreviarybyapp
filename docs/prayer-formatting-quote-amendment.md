# Поправка к контракту MyBrev: участники внутри Markdown blockquote

> Последующее обновление Flutter до утверждённого 1.1 описано в [текущем отчёте](prayer-formatting-parity-1.1.md). Ограничения этой поправки внутри цитат сохранены; прежнее ожидание остальных возможностей 1.1 относится к истории согласования.

Утверждена пользователем для Flutter 2026-10-14. Это изменение интерпретации текста при чтении; миграция Firestore и удаление `>` не требуются.

## Правило

Контейнер `blockquote` не запрещает семантическое выделение участника. В его обычных абзацах распознаются К./С./Н./Д./Л./Ц./V./R. по тем же консервативным правилам, что и вне цитаты: метка в начале физической реплики, необязательное наследуемое двоеточие, пробел/табуляция, непустые слова. Структурные `>` снимает Markdown parser только при построении AST, без изменения сохранённой строки.

```md
> Н. І з духам тваім.
```

Семантический результат:

```html
<blockquote><p><span class="prayer-speaker" data-role="people">Н.</span> І з духам тваім.</p></blockquote>
```

Метка красная жирная и наследует размер шрифта. Слова после неё имеют обычный стиль, если автор не выделил их Markdown. Отступ, вертикальная граница, переносы и вложенные цитаты сохраняются.

## Исключения

- `> С. Я. Купала`, `> К. Купала`: неоднозначные инициалы/имена, без роли.
- `> Тэкст: Н. І з духам тваім.`: метка не в начале самостоятельной реплики, без роли.
- `> C. Пан з вамі.`: латинский двойник не приравнивается к С.
- Inline/fenced/indented code, ссылки, заголовки, списки и `:::rubric` внутри цитат сохраняют свои исключения.
- `> **Н.** І з духам тваім.` сохраняет явное выделение по базовому 1.0; расширение наследуемых обёрток из PR #124 — отдельная будущая синхронизация.
- Ошибочно импортированный `>` тоже остаётся настоящим blockquote при чтении; смысловую правку источника может сделать только редактор. Глобального удаления `>` нет.
- Общие роли не передаются отдельному адаптеру Мессы.

## Сверка и передача веб-проекту

GitHub `main` MyBrev всё ещё содержит [контракт 1.0](https://github.com/senddownrain/mybrev/blob/8b02183667490ac50bb9982652512bdfc543a7aa/docs/prayer-formatting-standard.md), blob `f38c08df99459f02b65971e991210ac1121fad93`.
[PR #124](https://github.com/senddownrain/mybrev/pull/124), проверенный head `014cb8fdd446e3287d65164d25616612e468fcde`, предлагает 1.1 (обёртки strong/em, подтверждённые метки на отдельной строке, Усе:/Цэлебрант:, ограниченные явные указания). Эти дополнительные правила не включаются во Flutter без согласованного опубликованного контракта.

Поправка выше должна заменить глобальное исключение blockquote в обеих реализациях. Для веба: разрешить bare-prefix ranges внутри обычных абзацев blockquote на уровне AST, сохранив все остальные исключения; не переписывать источник, не снимать quote-контейнер. В `tests/prayer-formatting.test.mjs` добавить положительный пример выше и отрицательные кейсы из этого документа. Производственные данные и применение нормализатора не затрагиваются.

Flutter-проверки: `test/prayer_formatting_test.dart` (все восемь ролей, двоеточия, вложенные цитаты, слова и сохранённый источник); `test/prayer_formatting_widget_test.dart` (обычный стиль слов и жирные метки, одинаковые чтение/предпросмотр в обеих темах и крупном шрифте).

2026-10-14 поправка передана в существующий веб-чат «Форматирование» (MyBrev). Веб-проект реализовал её в [commit 0fcce378d6dd4b6f3d67a35fb45e44f49c5da4af](https://github.com/senddownrain/mybrev/commit/0fcce378d6dd4b6f3d67a35fb45e44f49c5da4af) текущего PR #124: renderer, текст контракта и положительные/отрицательные тесты обновлены. Проверены состояние OPEN, точный head и опубликованные исходники; слияние не выполнялось. Обе ветки теперь применяют одинаковое правило для bare-реплик в цитатах. Дополнительные возможности 1.1 по-прежнему остаются отдельной синхронизацией Flutter после согласования.
