## 2. Корневая причина `duplicate-app`

Воспроизведено на чистом симуляторе (тот же стек, что в #42). `GoogleService-Info.plist` лежит в `ios/Runner`, поэтому нативный FirebaseCore создаёт `[DEFAULT]` сам. В режиме эмуляторов (`PRIEST_USE_EMULATORS=true`, `DefaultFirebaseOptions.currentPlatform`) Dart передаёт **другие** `FirebaseOptions` (фиктивный `apiKey`, проект `demo-rules`). `firebase_core` (`method_channel_firebase.dart:131`) сравнивает `apiKey` нативного и переданного приложения и бросает `duplicate-app`. Для обычной (не эмуляторной) сборки опции совпадают с plist, поэтому TestFlight/магазинный путь этой ошибкой не затронут; проверено только по коду, собранный TestFlight build не запускался.
Первая версия фикса (проверка `Firebase.apps.isEmpty`) не работала: до первого `initializeApp` список `apps` в Dart пуст. Рабочий вариант — перехват `duplicate-app` и `Firebase.app()`.
Результат: приложение стартует до экрана часов (`I0-launch-after-fix.jpg`), ошибки `duplicate-app` в логе нет.
Побочно: с эмуляторными опциями приложение использует нативный `[DEFAULT]` (проект `ibreviaryby`), но `useFirestoreEmulator(localhost)` направляет Firestore на локальный хост; production не читается.
