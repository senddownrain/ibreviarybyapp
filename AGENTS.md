# Проверка Flutter

- Логика и парсеры: `dart format`, `flutter analyze`, целевые unit/widget-тесты через `flutter test`. После них запускать необходимые регрессионные тесты.
- Общий Flutter UI (экраны, форматирование, навигация, формы, темы, шрифт, адаптивность): дополнительно обязательна визуальная проверка именно Flutter Web в Google Chrome. Сначала `flutter devices`, затем существующий `run_in_chrome.bat` или `flutter run -d chrome`. Проверять изменённый экран, светлую/тёмную тему, крупный шрифт, мобильную ширину, прокрутку и ссылки. Синтетические данные изолировать от production Firestore.
- Воспроизводимый сценарий молитв: `flutter run -d chrome -t tool/prayer_formatting_smoke.dart --web-port 5237`. Widget-проверки: `flutter test test/prayer_formatting_widget_test.dart`. Браузерные unit/widget-команды допустимы только после проверки их конфигурации и фактического завершения; они не заменяют визуальную проверку.
- Для Chrome использовать точный локальный URL (у этого сценария `http://localhost:5237/`), а не заголовок окна Windows. При проблемах с графическим управлением подключаться напрямую к экземпляру Google Chrome, запущенному Flutter, через Chrome DevTools Protocol/подходящий браузерный инструмент; проверять URL вкладки. Не запускать бесконечно новые экземпляры. Сохранять реальные скриншоты в `audit-evidence/`, просматривать их и описывать проверенные состояния; без снимков и их проверки visual smoke не считать выполненным.
- Android-эмулятор не запускать по умолчанию ради общих UI/парсерных правок. Нативные возможности (плагины, разрешения, системная навигация, клавиатура, жизненный цикл, установка, Firebase на устройстве, магазин) проверять на целевой платформе. Перед мобильным релизом требуется отдельный native smoke-pass; Chrome не заменяет Android/iOS.
- Если Chrome недоступен, записать причину, выполненные альтернативы, пределы покрытия и команду воспроизведения. Сборка и headless-тесты не являются визуальной проверкой. Не ослаблять защиту или нативные зависимости ради web-smoke.
- В каждом PR кратко указать фактически выполненные unit/widget, Chrome visual smoke и native smoke (выполнен / не нужен / нужен перед релизом) и причину выбора.

## Защищённый интерфейс «Налады»

Контракт экрана, точные подписи и эталонные снимки находятся в [docs/ui/settings-screen-contract.md](docs/ui/settings-screen-contract.md).

Без согласования с владельцем запрещается:

- Менять порядок разделов, добавлять пункты настроек или возвращать удалённые пункты.
- Менять утверждённые подписи и значения по умолчанию.
- Выносить псалмодию из раздела «Тэкст» или менять утверждённый дизайн переключателей.
- Заменять страницу содержимым старой ветки или ослаблять контрактные тесты.

При слиянии веток и разрешении конфликтов сохранять утверждённую структуру. Согласованное изменение сопровождается обновлением контракта, тестов и эталонных снимков.
