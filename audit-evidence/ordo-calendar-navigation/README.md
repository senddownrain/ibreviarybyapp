# ORDO: прокрутка месяца и возврат назад

Начальная база: `f8a260ace2da371b871caef30e9a3656c1730d25` (PR #61).
За время проверки в main вошёл PR #63. Исправление перенесено без конфликтов
на актуальный `origin/main`, `7abba85bebe184e2314b6df1593bab0720fb1c77`.
Проверено 05.11.2026 UTC, Flutter 3.41.4 / Dart 3.11.1.

## Причины

Все пять исходных падений воспроизведены на неизменённом main `f8a260a`:

| Сценарий | Причина |
| --- | --- |
| Day → ORDO → Month → 02.11 → Back | При перелистывании октября на ноябрь автопрокрутка выбирала сегодняшнюю дату (05.11), хотя пользователь не выбирал её. Центр строки 02.11 оказался на `Offset(180, -145)`. Тап не дошёл до InkWell, новый OrdoScreen не открывался; поиск виджета выдавал `Bad state: No element` ещё **до** Back. |
| Dark, 1.0 | Та же автопрокрутка скрывала строку 01.11 за пределами viewport. |
| Dark, 1.5 | Та же причина; увеличение текста увеличивало высоту строк. |
| Light, 1.0 | Та же причина, независимо от темы. |
| Light, 1.5 | Та же причина, независимо от темы. |

Это времязависимый дефект интерфейса: переход стрелкой на текущий месяц
пропускал его начало. Неверных constraints, перекрытий или отсутствующего
обработчика нажатий не обнаружено. Месячный ORDO — вертикальный список
переменной высоты, не сетка. Он должен прокручиваться, а не уменьшать текст.

Стек маршрутов работает согласно `docs/ordo-flutter-port.md`: экран дня →
ORDO дня → месяц → ORDO выбранного дня. Back возвращает в тот же месяц с
прежним offset. Ожидание теста актуально; менять маршрутизатор не требуется.

Вторичная ошибка Riverpod была ошибкой teardown теста: контейнер освобождался
раньше дерева виджетов, затем сброс размера экрана вызывал metrics observer
TourHost, который ещё был mounted. Теперь тест сначала снимает дерево,
затем освобождает router и контейнер, затем сбрасывает viewport. Время жизни
production-провайдеров и навигационная архитектура не менялись.

## Изменения

- `lib/screens/ordo_month_screen.dart`: только исходно выбранная дата владеет
  якорем прокрутки. Другой месяц открывается с 1-го числа, включая текущий.
  Подсветка сегодня, выбор даты, исходный якорь и scroll offset при Back сохранены.
- `test/ordo_day_flow_test.dart`: корректный teardown, исходный сценарий с
  реальной кнопкой Back, проверка выхода на Home, матрица Light/Dark × 1.0/1.5
  на 390/320 px. Проверяются нажатия 01.11, соседние даты, сохранение ненулевого
  offset после открытия 15.11 и моделирование системного Back через `handlePopRoute`.
- `test/ordo_ux_test.dart`: корректный teardown, независимая от фиксированного
  ноября регрессия для системного текущего месяца, октябрь–ноябрь–декабрь,
  drag/scroll до 31.12, исходные проверки hit-test сохранены.

Литургические данные, Firestore, bundle/manifest, алгоритм чтений PR #61 и
другие экраны не изменялись.

## Ручная проверка Android (2–3 минуты)

1. На небольшом экране откройте 07.10.2026 → ORDO → «Ordo месяца».
   Ожидается октябрь с видимым выбранным днём.
2. Перелистните на ноябрь: виден день 01.11. Нажмите его, затем стрелку
   следующего дня: открывается 02.11. Кнопка Back возвращает в ноябрь.
3. Прокрутите ноябрь к 15-му, откройте его и нажмите системную Back:
   сохраняются ноябрь и положение прокрутки. Ещё Back возвращает к ORDO,
   затем на экран дня без ошибки.
4. Снова откройте месяц и проверьте октябрь ↔ ноябрь ↔ декабрь, прокрутите
   декабрь до 31-го и вернитесь: месяцы переключаются, строки доступны для
   нажатия, список не обрезан.
5. Повторите шаги 1–4 в Dark и Light с системным масштабом текста 1.5
   (первый проход — 1.0): кнопки, даты и прокрутка работают, текст без overflow.
